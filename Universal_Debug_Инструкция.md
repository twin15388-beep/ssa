# Universal Game Debug 1.2

**Основной файл: `Universal_Game_Debug.lua`.** Самостоятельный сборщик со встроенным Lumen UI, без привязки к прежней игре или PlaceId. Запускай весь файл в новой игре.

## Как прислать один отчёт

На вкладке **scan**, последовательно, каждый раз дожидаясь завершения:

1. **Game overview (no source)** — дерево доступных игровых объектов, remotes, атрибуты, модели, предметы, prompts и метаданные скриптов. Исходники в этом проходе не запрашиваются.
2. **ReplicatedStorage + decompile** — попытка чтения/декомпиляции скриптов из ReplicatedStorage.
3. **Local client scripts + decompile** — PlayerScripts, PlayerGui, текущий персонаж, Backpack локального игрока и ReplicatedFirst. Если PlayerScripts отсутствует, используется StarterPlayerScripts.
4. На вкладке **export** нажми **Save ALL scans (.json)** либо **COPY ALL SCANS**.
5. Пришли полученный JSON. Теперь это один корректный JSON-документ с массивом `reports`, а не несколько объектов, склеенных подряд.

**RightControl** — меню. **Cancel** — остановить текущий сбор и сохранить частичный результат. **Unload collector** — отключить обработчики и убрать окно.

Последний законченный или отменённый проход каждого профиля хранится в памяти. Повторный проход того же профиля заменяет предыдущий. Отчёты профилей сделаны в разные моменты времени, а не как единый атомарный снимок.

## Экспорт отдельных разделов

Старые функции сохранены:

- **Saved scan** — выбрать сохранённый профиль;
- **Section** — Full report, Remotes, Scripts, Interactives, Models, Tree, Logs;
- **Export path filter** — фильтрация разделов по пути;
- **COPY REPORT** / **Save report (.json)** — выбранный отчёт/раздел;
- **Manual copy / view** — ручное копирование с разбивкой большого текста на страницы.

**COPY ALL SCANS / Save ALL scans игнорируют фильтр и Section**, включая полные сохранённые отчёты. Для большого объёма предпочтительнее файл. Сохранение требует `writefile` и создаёт файл в пространстве среды выполнения, а не в папке этого чата. Если API буфера недоступен, используется ручное копирование.

## Что исправлено

- Явно универсальное окно: текущий PlaceId показан внизу. Нет игровых запросов или зависимостей от старой игры.
- Добавлен отдельный проход обзора без исходников.
- Несколько профилей можно объединить в один JSON.
- Кнопки профилей **учитывают выбранный Max source scripts**, а не сбрасывают его на 250.
- Ошибки вида `-- Error: ...` вместо кода больше не считаются успешным восстановлением исходника, если результат содержит только комментарии и распознанную диагностику.

Для обнаруженного текста ошибки сохраняются:

- `sourceStatus = "decompiler returned error text instead of source"`;
- `sourceErrorKind = "decompiler_diagnostic_only"`;
- `decompilerDiagnostic` — до 4 000 байт текста;
- `stats.sourceDiagnosticErrors` и `stats.sourceFailures` увеличиваются;
- `stats.sourceIncomplete` становится true.

Если маркер ошибки находится рядом с кодом, текст сохраняется с `sourceWarning`. Это **эвристическая проверка**, не полноценный парсер: она не ловит все сбои декомпилятора и не доказывает корректность остальных текстов. Оригинальное Source-свойство этой эвристикой не отбрасывается.

## Лимиты и другие папки

- По умолчанию до **20 000 объектов**, настройка до 60 000.
- По умолчанию до **250 исходников**, настройка до 500.
- До **4 МБ исходников суммарно на проход**, до 160 КБ на скрипт.
- Около 12 МБ метаданных узлов на проход; итоговый отчёт может быть больше из-за индексов и исходников.
- До 5 секунд на попытку Source и отдельно на попытку декомпиляции. Тайм-аут кооперативный: блокирующий нативный декомпилятор не всегда можно прервать.
- CorePackages, CoreGui и внутренние сервисы движка не обходятся.

Если нужные модули находятся, например, в Workspace, используй **Scan game (manual settings)** с включённым **Read available source**, при необходимости **Try executor decompile fallback** и фильтром **Source path contains**. Готовые профили ReplicatedStorage/Local client очищают этот фильтр и сами включают попытку чтения и декомпиляции. Источники включаются только явным действием пользователя; старые конфиги автоматически не подгружаются.

После сбора проверяй `stats.incomplete`, `treeIncomplete`, `sourceIncomplete`, количество пропусков по лимитам, `sourceFailures`, `sourceTruncatedCount` и статусы отдельных записей. Достигнутый лимит не означает, что остальные объекты/скрипты отсутствуют.

## Ограничения и приватность

- Сборщик читает только доступные клиенту данные. Серверные исходники, которые не реплицируются, недоступны.
- StreamingEnabled может скрывать удалённые части мира. Сначала подойди к нужной области, если она не загрузилась.
- Список remotes не раскрывает серверные обработчики или схему аргументов. Перехвата вызовов здесь нет.
- Декомпиляция зависит от среды, может быть неполной или ошибочной и не является гарантированной деобфускацией.
- Скрипт **не вызывает игровые remotes, не делает require найденных модулей и не отправляет отчёты по HTTP**.
- В отчёте могут быть приватные пути, имена, тексты интерфейса, исходники и логи. Проверь файл перед публикацией; анализируй исходники, на доступ к которым у тебя есть разрешение.
- В обычном Studio LocalScript нет стандартного доступа к системному буферу, файловому API executor и декомпилятору; применимы ручной экспорт и доступные клиентские API.

## Проверка

Проверены синтаксис самостоятельного Lua-файла и логика на тестовых объектах: отсутствие привязки к старому PlaceId, обзор без исходников, оба профиля, лимит исходников, распознавание двух типов диагностических заглушек, сохранение кода с предупреждением, объединение трёх отчётов в валидный JSON и сохранение файла. Регрессионные проверки экспорта, лимитов и выгрузки также пройдены.

**В реальном Roblox-клиенте новой игры эта версия здесь не запускалась.** Совместимость UI, декомпилятора и API буфера/файлов нужно проверить в твоей среде.
