# Debug одной кнопкой — v1.5

Файл: **CAM_Debug_OneClick_v1.5.lua**. Самостоятельный, никаких дополнительных библиотек скачивать не нужно.

## Что делать

1. Зайди в нужную игру. Если CAM Main уже открыт, **оставь его загруженным**, но останови автоматизации. Для более полезного журнала можно перед остановкой повторить неработающую кнопку M1 once. Это необязательно для сбора исходников.
2. Запусти **весь** новый debug-файл.
3. Нажми **COLLECT + SAVE + COPY** один раз.
4. Дождись **SAVED** или **COPIED**. Строка `Scan ready` ещё не конец: после неё идёт упаковка и экспорт.
5. Пришли файл **CAM_Debug_OneClick_<PlaceId>_<дата>.json** из рабочей папки (workspace) исполнителя. Точное имя покажется в меню. Если сохранение недоступно, JSON автоматически отправляется в буфер: вставь его в текстовый файл и пришли файл.

**RightShift** скрывает/показывает debug. В отличие от старого коллектора, UI этой версии использует отдельную переменную и не выгружает CAM Main при запуске.

Если не работают ни сохранение, ни буфер, откроется ручное копирование по страницам: нужно соединить все страницы по порядку. При наличии хотя бы одного исправного API дополнительных кнопок экспорта не требуется. Большой буфер может обрезаться на стороне исполнителя — сохранённый JSON предпочтительнее.

## Что собирает

- Недостающие `CAM.Client.Modules.GamePlay.Dialogue` и `Regions`.
- Квестовые модули/QuestStates, ограничения toolbar и экипировки, Dash_Handler, Shop и связанные контроллеры ввода/навыков — 12 точечных корней, без полного повторного обзора всех эффектов игры.
- Автоматически найденные модули Toolbar/Skills и клиентские Layout/Combat внутри заданных контейнеров — до 30 дополнительных корней.
- Название/версию исполнителя, если доступен API определения, и признаки устройства.
- Снимок диагностики **нашего** CAM Main, если он присутствует в том же окружении.
- Состояние персонажа, экипировки, toolbar/инвентаря, квестов, меню, SHC/SHCS и видимости диалога.
- Доступную историю клиентских сообщений/ошибок; список загруженных модулей, если API поддерживается.

Наличие модуля не означает наличие работающего обработчика ввода. Сборщик сам не нажимает M1 и потому не выдаёт отчёт за активный тест боевой цепочки.

## Ограничения и безопасность

Нет игровых remote-вызовов, атак, использования предметов, `require` найденных игровых модулей, hooks или HTTP-выгрузки. Декомпиляция использует доступную функцию исполнителя; сам текст не выполняется. Единственный вызов нашего main — его собственный read-only `Snapshot()`.

Ограничения: 15 000 узлов, 500 исходников, 4 МБ суммарного текста исходников, 160 КБ на один исходник, ограниченное ожидание чтения/декомпиляции. Отсутствующие корни, ошибки, лимиты и обрезания отмечаются в JSON. Компактные снимки состояния имеют собственные флаги `incomplete`; ошибки снимка — `runtimeBefore.errors` / `runtimeAfter.errors`. Серверные скрипты недоступны.

При отказе штатного JSON-кодировщика применяется проверенный резервный кодировщик v1.4; нормализации видны в `_jsonExport`. Это не гарантирует побайтовое сохранение некорректных UTF-8-атрибутов.

Отчёт может содержать имя персонажа, состояние инвентаря, исходники и сообщения консоли. Проверь его перед публичной публикацией. Автоматической отправки куда-либо нет.

Кнопка отмены во время сканирования сохраняет возможность экспорта частичного результата. Если отменён именно экспорт, можно нажать **Export cached result again** без повторного сканирования.

Проверены синтаксис standalone-файла и имитационные сценарии: один запуск кнопки, автоматические save/copy, динамическое обнаружение Toolbar, недостающий корень, отсутствие main, отказ штатного JSON, независимые ошибки writefile/clipboard, ручной запасной вариант и изоляция UI от main. Живого теста в Roblox здесь нет.
