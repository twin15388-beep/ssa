# CAM Main Hub 2.0

Переработанный основной скрипт для PlaceId **136406881576517**, по присланным исходникам версии игры **5354**. Это main, не новый сборщик.

**Файл запуска: `CAM_Main_Hub_v2.0.lua`.** Он самостоятельный: интерфейс, каталог и логика внутри, скачивать дополнительные Lua-файлы не нужно. HTTP-загрузок кода нет.

> Проверены синтаксис и сценарии на имитации Roblox API. Реального запуска в Roblox/Potassium и подтверждения серверного результата у автора нет. Не следует считать эту сборку уже проверенной в игре или полной реализацией всех функций исходного Ouroboros Hub.

## Быстрый запуск — для твоего персонажа

1. Если открыт старый main, нажми в нём **Unload hub**. Новая версия также пытается выгрузить обнаруженный предыдущий `CAMMainHub`.
2. Выполни **`CAM_Main_Hub_v2.0.lua`** в исполнителе.
3. Открой **auto level** → включи **Auto Level - accept / farm / repeat**.
4. Дополнительно включать Auto Farm или Auto M1 не нужно. Загрузка штатных модулей начинается автоматически при включении Auto Level.
5. На **dashboard** смотри текущую фазу, уровень, квест и прогресс.

По последнему отчёту твой уровень — **8**, раса — Human. При доступности штатных требований политика `Highest eligible` выберет **Zuko у Krue**, порог 7. После перехода на уровень 10 следующий новый квест — **Bear Cub у Tom**. Уже принятый поддерживаемый квест сначала заканчивается: хаб не бросает его при повышении уровня посреди задания.

Если бой с боссом слишком тяжёлый, переключи **Quest policy → Mobs only**. На уровне 8 это оставит обычных бандитов. Позиция сверху не делает персонажа неуязвимым.

### Клавиши

- **RightCtrl** — показать/скрыть main.
- **End** — STOP: выключить автоматизации и убрать созданные хабом ограничения движения.
- **Unload hub** — остановить и выгрузить интерфейс.
- Если оставлен отдельный debug, его клавиша — **RightShift**. Singleton интерфейса main теперь отдельный: `CAMMainLumen`, debug — `CAMDebugLumen`.

Все автоматизации при запуске **OFF**, сохранённые конфигурации автоматически не включаются. Смерть, смена персонажа/команды и низкий HP останавливают автоматизации без автоматического возобновления.

## Что изменено по сравнению с 1.0

### 1. Auto Level — цикл, а не рекомендация

Реализованы:

1. Чтение уровня из `Exp.Goal / 60`.
2. Выбор наиболее высокого подходящего маршрута из каталога.
3. Проверка актуальных определений, требований квеста и NPC штатными модулями. Учитываются в том числе ограничения расы.
4. Перемещение к NPC-квестодателю.
5. Проверка `CanAddQuest` и штатный запрос `AddQuest` с точным ключом задания.
6. Ожидание появления квеста в `Data.Quests.Holder`. Отправка запроса **не** считается принятием.
7. Поиск соответствующего противника; если он не загружен, перемещение к известной точке появления и ожидание.
8. Позиционирование, подготовка оружия и M1.
9. Наблюдение за `Tasks.Value / Max` и закрытием квеста сервером.
10. Повторный выбор по новому уровню и повтор цикла с соблюдением штатного cooldown.

После отправки запроса хаб ждёт 8 секунд; после трёх попыток без появления квеста останавливается. Отказ штатной проверки, включая cooldown или занятый слот категории, не обходится.

**Завершение и награда:** в выбранном каталоге только простые повторяемые задания на убийства без отдельного шага доставки. Их закрытие ожидается от сервера. Исчезновение записи квеста фиксируется отдельно и само по себе не объявляется доказательством получения награды. Если все счётчики заполнены, но запись не закрывается 15 секунд, хаб останавливается. Несуществующий или неподтверждённый `CompleteQuest` не вызывается.

### 2. Обычный фарм — выбранная цель или ближайший противник

На **farm / combat**:

- **Selected mob** — отдельный список мобов.
- **Selected boss** — отдельный список боссов/одиночных боевых NPC, включая тренировочных противников.
- **Nearest hostile** — ближайший подходящий загруженный противник в радиусе. Выбранная цель удерживается, пока жива и остаётся в радиусе.
- **Auto Farm - selected / nearest** — движение + бой, без принятия квестов.
- **Auto M1 (no movement)** — атаки без перемещения.
- **Auto Skills** — выбранные штатные слоты способностей; это отдельная опция.

В каталоге **47 определений активных противников**. Это не означает, что все 47 одновременно присутствуют на сервере. Идентификация использует код NPC, точное имя или однозначное имя модели из исходников. Неизвестный Humanoid не считается врагом автоматически. Персонажи игроков не выбираются целью. Это не гарантия отсутствия случайного попадания штатным ударом по игроку рядом с мобом.

Выбранного моба/босса можно ждать у известной точки появления. В режиме ближайшего противника глобального поиска по незагруженной карте нет.

### 3. Позиционирование

На **farm position** доступны:

- **Above** — по умолчанию;
- Below;
- Behind;
- In front;
- Left;
- Right;
- Orbit;
- Ground.

Настройки: расстояние, высота, скорость вращения, направление взгляда (`Horizontal / Full 3D / Off`) и способ перемещения.

| Настройка | По умолчанию |
|---|---|
| Позиция | Above |
| Высота | 3 studs |
| Расстояние | 2 studs |
| Перемещение | Tween |
| Скорость | 80 studs/sec |
| Взгляд | Horizontal |
| Радиус M1 | 7 studs |
| Минимальный интервал M1 | 0,5 сек., с учётом штатного cooldown |
| STOP по HP | 25% |
| STOP при отсутствии уменьшения HP цели | 20 сек. |

`Tween` здесь — плавное линейное перемещение с ограничением скорости на каждом кадре, а не объект TweenService. `Instant` — непосредственная смена позиции. `Walk` — штатный MoveTo: он **не умеет зависать**, поэтому для него подходит Ground.

Удержание в воздухе создаётся только для своего персонажа во время движения/фарма. При остановке созданные объекты удаляются, AutoRotate восстанавливается. Само по себе положение сверху не отключает атаки противников, stun, серверную коррекцию или урон. Завышенная высота/дистанция может приводить к промахам M1.

Маршруты прямые, без полноценного поиска пути вокруг стен. При блокировке или коррекции движения без прогресса 8 секунд автоматизации останавливаются. Отдельный Noclip остаётся явной опцией, автоматически не включается.

### 4. Подготовка оружия и другой путь M1

`Combat weapon → Auto combat tool` сохраняет подходящее уже выбранное оружие. Иначе проверяет существующие слоты в порядке 3, 1, 2, 4, 5. В твоём отчёте Tanto стоит в третьем слоте, Combat — в первом.

Проверяются боевое назначение предмета, штатные запреты и требования экипировки. Инвентарь и toolbar не переписываются; покупок нет. Изменяется штатное поле выбранного **индекса слота** — это не ID предмета. Далее работают обработчики экипировки самой игры.

Способы M1:

1. **Auto (live punch / native input):** если исполнитель предоставляет рабочий `getsenv`, используется существующая функция `punch` из `PlayerScripts.CU.Combat`. Это штатная функция с её проверками и cooldown, не повторная инициализация Combat LocalScript.
2. Если доступ к функции отсутствует — штатный `InputHandler`.
3. **Native input only:** принудительно оставить только InputHandler.

Синтетических щелчков мышью по экрану нет, чтобы не нажимать кнопки хаба вместо атаки. Поддержка `getsenv` именно в твоей версии Potassium не подтверждена отчётом — проверяется при выполнении.

Диагностика различает запрос атаки, изменение штатного `ComboTrackerClient.Time` и наблюдение уменьшения HP цели. Изменение комбо не доказывает серверное попадание, а уменьшение HP не приписывается безусловно своему удару.

Если оружие не готово 15 секунд, нативный вызов завис более чем на 10 секунд или здоровье цели не уменьшается в течение выбранного интервала, автоматизации останавливаются с причиной. Уже запущенное внутреннее действие игры STOP не может отменить задним числом, но новые запросы хаб перестаёт отправлять.

## Остальные разделы

Сохранены прежние интеграции, без заявления о новой live-проверке:

- выбранные слоты штатных skills;
- получение рекомендаций игры и выбранных Boss Hunts;
- ближайшие штатные loot/chest prompts с проверкой расстояния и видимости;
- локальное сокращение удержания prompt — не обход серверных условий;
- fly, noclip, speed/jump overrides, штатный Run/Shift Lock;
- телепорты к загруженным объектам;
- ESP и локальные уведомления.

**Не реализованы:** доставка/escort/fishing-циклы, очереди/ранкед/подземелья/карточки и волны, автоматическое платное обучение и распределение skill points, покупки, смена расы, универсальный parry/heal-бот, infinite stamina, invulnerability, instant kill, server-wide bring enemies, webhooks. В интерфейсе это список ограничений, а не пустые рабочие переключатели.

## Что означает статус

| Сообщение / фаза | Значение |
|---|---|
| Travel to NPC | Перемещение к квестодателю |
| Await acceptance | Запрос отправлен, появления квеста ещё нет |
| Cooldown / eligibility | Штатная проверка пока запрещает принять квест |
| Farm | Квест обнаружен в данных, идёт поиск/бой |
| Waiting for spawn / streaming | Нужный противник ещё не появился или не загружен |
| Await server completion | Задачи заполнены, ожидается закрытие записи |
| No native combo / damage | Не наблюдалось запуска комбо и уменьшения HP; возможна проблема ввода/экипировки |
| No target HP decrease | Комбо наблюдалось, но HP не уменьшается: возможны промахи, высота, дистанция, неуязвимость цели |
| Quest not acknowledged | Три запроса без появления квеста; хаб остановлен |
| Movement blocked/corrected | Движение не даёт прогресса |
| Paused: text entry / native menu | Ввод текста или открыто игровое меню; действия приостановлены |

При открытом меню игры скрипт намеренно не атакует. Перед включением фарма закрой инвентарь/диалог и выйди из текстового поля.

## Встроенная диагностика

На **diagnostics / limits** есть одна кнопка:

**ONE CLICK - save + copy main diagnostics**

Она формирует один небольшой JSON, пытается сохранить `CAM_Main_YYYYMMDD_HHMMSS.json` и скопировать тот же текст. При недоступности обоих API открывает текст на экране. Успех clipboard API не является проверкой целостности содержимого системного буфера.

В отчёте: версия, параметры, фаза, состояния модулей, выбранный маршрут, попытки принятия, backend M1, наблюдения комбо/HP, список до 60 загруженных неигровых Humanoid и журнал причин остановки. Ничего никуда автоматически не отправляется.

## Что проверено перед выдачей

- Синтаксис самостоятельного Lua-файла.
- Отсутствие старта автоматизаций и require-вызовов до явного включения/Connect.
- Автоподключение 11 разрешённых штатных модулей.
- Выбор Zuko на уровне 8 и Bear Cub после перехода на 10.
- Отсутствие боя до появления принятого квеста в данных.
- Ожидание завершения, повтор цикла, cooldown и ограничение повторных запросов.
- Проверка изменённого определения с платой: такой маршрут не принимается.
- Экипировка индексом слота, запреты экипировки, нативный punch и резервный ввод.
- Все восемь режимов позиционирования.
- Исключение игроков/неизвестных NPC, watchdog без урона, low HP/focus/wrong-place/STOP/unload.
- Одинаковый JSON при сохранении и копировании одной кнопкой.

**Это проверки на имитации API, не результат игры на сервере.** Причина отсутствия действий у старой 1.0 не установлена окончательно: в присланных отчётах её рабочее состояние не обнаруживалось. Версия 2.0 меняет реализацию и добавляет наблюдаемые критерии работы, но не выдаёт предположение о причине за установленный факт.
