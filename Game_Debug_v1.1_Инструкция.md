# Game Debug Collector 1.1

Отдельный Lua-файл со встроенным Lumen UI. Замена версии 1.0; дописывать код в старый файл не нужно.

## Быстрый сбор двух отчётов

1. Запусти **весь** `Game_Debug_Collector_v1.1.lua` на клиенте Roblox.
2. На вкладке **scan** нажми **ReplicatedStorage + decompile**.
3. Дождись уведомления о готовности. Открой **export → Save report (.json)** или **COPY REPORT**.
4. Вернись в **scan** и нажми **Local client scripts + decompile**.
5. После завершения сохрани/скопируй второй отчёт.
6. Отправь два отчёта отдельными файлами. Сам Lua-файл сборщика вместо отчёта отправлять не нужно.

Обе кнопки сами включают чтение исходников и попытку декомпиляции, очищают фильтр исходников, устанавливают лимит 250 скриптов и выбирают раздел **Scripts** для экспорта. Переключать настройки вручную не требуется.

**RightControl** — скрыть/показать меню.

## Что изменилось

- **CorePackages, CoreGui, RobloxReplicatedStorage и внутренние сервисы движка не обходятся.** В общем профиле используется список игровых корней, а не все дочерние объекты game.
- **Профиль ReplicatedStorage** сканирует только эту папку и её потомков, без всего Workspace и других игроков.
- **Профиль Local client** сканирует PlayerScripts, PlayerGui, текущего персонажа и Backpack только локального игрока, а также ReplicatedFirst. Если PlayerScripts отсутствует, используется StarterPlayerScripts. Это уменьшает повторный сбор одинаковых скриптов у разных персонажей.
- Метаданные видимых серверных Script могут попасть в отчёт, но попытки получить исходники направлены на ModuleScript, LocalScript и Script с клиентским RunContext.
- **Настройки, выбранный профиль, фактические корни, возможности среды и ошибки включены в экспорт Scripts.** Теперь по присланному файлу можно проверить режим сбора.
- Отдельно подсчитываются попытки, ошибки, тайм-ауты, усечённые исходники, пропуски из-за лимитов и уникальные полные тексты, возвращённые средой.
- Последний завершённый отчёт каждого профиля хранится в памяти. В **Saved scan** можно выбрать `ReplicatedStorage`, `Local client`, `Game` или `Latest`. Поле **Active report** показывает, какой отчёт сейчас будет скопирован.
- Имя сохраняемого JSON включает профиль, PlaceId и время.

Дубликаты текста в пределах одного профиля не удаляются из отчёта: сохраняются соответствия отдельным объектам. Число уникальных текстов доступно в `stats.sourceUniqueTexts`.

## Ручной режим

**Scan game (manual settings)** обходит:

- ReplicatedStorage, ReplicatedFirst;
- StarterPlayer, StarterGui, StarterPack;
- Workspace, Players;
- Lighting, SoundService, Teams.

Он использует текущие переключатели чтения исходника и декомпиляции, фильтр **Source path contains** и лимиты. При первом запуске версии 1.1 чтение исходников в ручном режиме выключено. После применения готового профиля переключатели остаются включёнными и видны в UI.

Фильтр исходников применяется только к выбору скриптов для чтения, а не ко всему обходу дерева. **Export path filter** фильтрует готовые записи; к включению декомпиляции отношения не имеет.

В ручном режиме лимит исходников можно выбрать от 1 до 500. Готовые профили всегда возвращают его к 250. Максимум объектов по умолчанию 20 000, настраивается до 60 000.

## Лимиты и полнота

- Около 12 МБ сериализованных метаданных узлов до остановки обхода; итоговый JSON может быть больше из-за индексов и текстов.
- До 4 МБ исходников суммарно и 160 КБ на один скрипт.
- До 5 секунд на отдельную попытку чтения Source или декомпиляции; при использовании обоих способов время может суммироваться.
- Тайм-аут кооперативный. Если нативный декомпилятор блокирует клиент, принудительную остановку гарантировать нельзя.
- StreamingEnabled и права клиента по-прежнему ограничивают доступные объекты. Сканирование — не атомарный снимок; игра может менять объекты во время обхода.

Полезные поля отчёта:

| Поле | Значение |
|---|---|
| `settings.profile` | Выбранный профиль |
| `settings.sources`, `settings.decompile` | Запрошены ли исходники и запасная декомпиляция |
| `roots` | Какие корни реально обходились |
| `stats.sourcesCollected` | Сколько непустых текстов вернула среда |
| `stats.sourceUniqueTexts` | Сколько среди них уникальных полных текстов до усечения |
| `stats.sourceCountLimitSkipped` | Сколько подходящих скриптов пропущено из-за лимита количества |
| `stats.sourceBytesLimitSkipped` | Сколько пропущено после исчерпания бюджета исходников |
| `stats.sourceFailures` | Неудачные попытки получить текст |
| `stats.sourceTimeouts` | Неудачи с итоговым статусом тайм-аута |
| `stats.sourceTruncatedCount` | Сколько полученных текстов пришлось усечь |
| `stats.treeIncomplete` | Обход остановлен лимитом, отменён или завершился ошибкой |
| `stats.sourceIncomplete` | Есть пропуски, ошибки, отмена, усечение или незавершённые попытки получения исходников |
| `stats.incomplete` | Общий признак неполноты по указанным причинам |
| `records[].sourceStatus` | Результат для конкретного скрипта |

Даже `incomplete: false` **не означает**, что получена вся игра: это относится лишь к выбранным доступным клиенту корням и обработанным объектам. `sourcesCollected` считает возвращённые строки, а не проверенные корректные исходники.

## Буфер, файлы и приватность

- Копирование использует доступный API буфера среды выполнения. Если он отсутствует/выдаёт ошибку, открывается ручное копирование с разбивкой на страницы.
- Сохранение требует реального `writefile`; файл создаётся в файловом пространстве среды выполнения, не в папке этого чата.
- В Studio обычному LocalScript недоступны системный буфер, writefile и встроенная декомпиляция; остаётся ручной экспорт и то, что разрешает клиентский API.
- Сборщик не вызывает игровые remotes, не перехватывает их и не выполняет require найденных модулей. Автоматической отправки отчётов нет.
- Декомпиляция не равна полной деобфускации. Серверные исходники, не реплицируемые клиенту, недоступны. Возвращённый текст может быть ошибочным.
- Перед передачей отчёта проверь его: GUI, атрибуты, исходники и логи могут содержать приватные сведения.
- **Unload collector** отключает обработчики сборщика. Запуск заменяет предыдущее окно Lumen, но не гарантирует остановку фоновой логики стороннего хаба.

## Проверка версии

Проверен синтаксис полного Lua-файла. На тестовых объектах проверены исключение CorePackages, оба готовых профиля, автоматические настройки, экспорт настроек, переключение сохранённых отчётов, усечение исходников, лимит количества, фильтр экспорта и выгрузка. В реальном Roblox-клиенте и конкретной среде выполнения версия здесь не запускалась.
