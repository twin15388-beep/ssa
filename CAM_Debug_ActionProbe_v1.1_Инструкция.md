# CAM Debug ActionProbe v1.1 — Инструкция (обновление после v1.0)

## Что нового по сравнению с v1.0 (анализ ваших записей показал 3 проблемы)

1. **Дедупликация хуков.** В ваших записях каждое событие повторялось ~10 раз. Причина: повторные нажатия ATTACH цепляли хук поверх хука. Теперь функции/кнопки/тапли помечаются один раз (weak-таблица), повторные ATTACH безопасны. В экспорте будет маркер `ATTACH | taps now: N` — сверим количество тапов между заходами.
2. **Новый тап: `__namecall` remote-спай (самое важное).** В записях v1.0 НЕ оказалось ни одного сигнала покупки в магазине и разблокировки навыка в дереве — этот трафик идёт не через модульный `ToServer`, а напрямую через `RemoteEvent:FireServer()` / `RemoteFunction:InvokeServer()`. Теперь пробник перехватывает эти вызовы через `hookmetamethod` и пишет их с направлением `C2S.remote` и полным путём ремоута (например `ReplicatedStorage.X.Shop.BuyRemote`). Результаты `InvokeServer` тоже записываются. Лимит: 80 записей на один путь.
3. **Лимит сигналов 1500** (было 900), **кнопки тоже дедуплицированы**.

Требование: ваш executor должен иметь `hookmetamethod` (DagHub/синапс-подобные имеют). Если нет — ATTACH запишет ошибку `hookmetamethod failed` в экспорт, остальные тапы продолжат работать.

## Базовый порядок (как в v1.0)

1. Запустите `CAM_Debug_ActionProbe_v1.1.lua`.
2. Нажмите **1) ATTACH** один раз (проверьте, что в экспорте `taps` ≥ 3: два модульных тапа + `__namecall remote spy`).
3. Нажмите **2) START**.
4. Выполните ОДНО действие.
5. Нажмите **EXPORT & COPY** → сохраните JSON → сбросьте мне.
6. **2) STOP** перед следующим сценарием, потом снова START.

## Запросы на новые записи (приоритет сверху вниз)

| Приоритет | Сценарий | Что сделать в игре (после START!, не до) |
|---|---|---|
| 1 | Магазин | Нажать маркер «Shop purchase…», затем купите **любой реальный дешёвый предмет** за валюту. Нам нужен полный протокол покупки (remote + первые 3 аргумента). |
| 2 | Дерево навыков | Маркер «Skill tree…», затем в дереве нажмите **START/Unlock любого узла, который сейчас доступен**. В v1.0 эта запись была пустой, потому что START нажимался позже — теперь нажмите START ДО действия в дереве. |
| 3 | Тренировка до конца | Маркер «Training…», затем **полностью закончите одну тренировку** с результатом «успех». В v1.0 были только fail/cancel — нам нужен успешный сигнал (`Stop,true`?). |
| 4 | Рыбалка | Маркер (если есть) + закиньте удочку и выиграйте один мини-гейм. |
| 5 | Блок-парирование (для Auto Parry) | Маркер «Block...», затем подержите блок у НПЦ, чтобы сработал Perfect — зафиксируем `Values/Blocking/Perfect`. |

## Важно

- **Не нажимайте ATTACH много раз подряд** — теперь это безвредно, но засоряет маркеры.
- Записей «кнопок» в v1.0 не было: игра, видимо, использует кастомные кадры. Если после v1.1 кликов по магазину всё равно нет в `buttons`, это нормально — главный канал теперь `C2S.remote`.
- Экспорт пишется в `CAM_ActionProbe_<utc>.json` в папку workspace executor'а (кнопка показывает путь) и копируется в буфер обмена.
- Полный сброс без перезапуска: кнопка **4) Unload everything** (возвращает { ... } и/или строку вида `[Probe] unloaded`, снимает хуки, включая `__namecall`).

После того как пришлёте новые записи — соберём Auto Shop / Skill Tree / Training(true) в основной сборке v2.3.x. Уже в работе: **Auto Parry (beta) в v2.3.0** — сигнатуры `Values/Blocking` + `Perfect/PerfectNpc` подтверждены вашей записью.
