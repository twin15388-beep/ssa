# Game Debug Collector — Lumen UI

Отдельный клиентский сборщик диагностики на UI из присланного `Blox Fruit.txt`. Код фарма, боя и покупок из примера не включён.

## Запуск

1. Открой `Game_Debug_Collector.lua` и скопируй **весь файл** в клиентскую среду выполнения Roblox. В своём проекте Studio можно использовать LocalScript в StarterPlayerScripts.
2. На вкладке **scan** нажми **Scan game**.
3. Дождись `Done`. **Cancel** останавливает сбор с сохранением частичного результата.
4. На вкладке **export** выбери раздел и нажми **COPY REPORT**.
5. **Save report (.json)** сохраняет отчёт в файловое пространство среды выполнения, если доступен `writefile`.

**RightControl** — показать/скрыть окно. **Unload collector** — остановить сборщик и отключить его обработчики логов.

Библиотека использует глобальный `Lumen`: при запуске заменяет уже открытое окно этой библиотеки. Это НЕ гарантирует остановку фоновых задач другого хаба; лучше запускать сборщик отдельно от примера.

## Что попадает в отчёт

- PlaceId, UniverseId, версия места, состояние StreamingEnabled и параметры Workspace.
- Доступное клиенту дерево объектов: ID узла и родителя, класс, путь, атрибуты, теги.
- RemoteEvent, RemoteFunction, UnreliableRemoteEvent, BindableEvent и BindableFunction.
- ModuleScript, LocalScript и прочие видимые контейнеры скриптов: метаданные и статус получения исходника.
- Модели, наличие Humanoid, позиции и размеры деталей, здоровье, ValueBase.
- Tool, ProximityPrompt, ClickDetector и TouchTransmitter.
- Текст доступного UI, идентификаторы Animation и Sound.
- До 200 сообщений в буфере логов; попытка получить последние 100 сообщений истории, новые сообщения и доступные ScriptContext.Error.
- Статистика, лимиты, отмена и ошибки самого сбора.

Полный отчёт — JSON. В меню экспорта можно отдельно скопировать Remotes, Scripts, Interactives, Models, Tree или Logs. Фильтр пути применяется к выбранным разделам, но не к Full report и Logs. Логи обновляются при экспорте; состояние объектов — снимок на момент сканирования.

CoreGui и собственное окно сборщика исключены. Node ID помогает различать объекты с одинаковыми именами; текстовый путь не является исполняемым выражением Lua.

## Исходники, декомпиляция и деобфускация

По умолчанию исходники **не собираются**.

Для попытки получения исходников:

1. Включи **Read available source**.
2. При необходимости включи **Try executor decompile fallback**.
3. Желательно задай **Source path contains** — например, часть имени нужной папки или модуля.
4. Запусти новый Scan.

Сначала сборщик пробует читать `Source`. Если чтение недоступно, а второй переключатель включён и среда предоставляет функцию `decompile`, используется эта функция. Полученный текст сохраняется в поле `source`, способ/ошибка — в `sourceStatus`.

**Это не универсальный деобфускатор.** Декомпиляция может вернуть неполный, ошибочный или по-прежнему обфусцированный текст. Сборщик не выполняет полученные исходники и не делает `require()` найденных модулей. Для настоящего анализа обфускации нужен конкретный исходник или дамп.

Исходники серверной логики, которая не реплицируется клиенту, получить этим способом нельзя. Видимый объект Script не означает, что его серверный исходник доступен. Аргументы remotes, серверные обработчики и смысл протокола также не определяются по одному списку объектов: перехвата вызовов здесь нет.

## Ограничения

- По умолчанию до 20 000 объектов; в UI можно выбрать 1 000–60 000. Очередь обхода тоже ограничена.
- Около 12 МБ сериализованных метаданных узлов до остановки обхода. Итоговый JSON может быть больше из-за индексов и исходников.
- По умолчанию до 50 попыток сбора исходников, максимум 250.
- До 160 КБ текста на скрипт и 4 МБ исходников суммарно. Усечение отмечается отдельно.
- До 5 секунд на попытку чтения/декомпиляции. Тайм-аут кооперативный: если нативная функция среды блокирует клиент целиком, сборщик не может гарантированно прервать её.
- `stats.completed` означает завершение прохода, а не полноту игры. Проверяй также `stats.incomplete`, `queueLimitReached`, `metadataLimitReached`, `errors` и статусы отдельных исходников.
- StreamingEnabled, разрешения клиента, удаление объектов во время обхода и лимиты могут сделать отчёт неполным. Перейди в нужную область и повтори сбор, если объекты ещё не загрузились.

## Буфер обмена и приватность

Автокопирование требует `setclipboard`, `toclipboard` или `Clipboard.set`. В обычном Roblox/Studio прямого доступа к системному буферу нет. При отсутствии API открывается ручное копирование: **Select all → Ctrl+C**. Большой отчёт разбивается на страницы; их нужно соединять по порядку без добавления разделителей. Для крупных отчётов лучше использовать сохранение файла, если оно поддерживается.

Сборщик ничего не отправляет по сети и не вызывает игровые remotes. Но локальный отчёт может содержать имена игроков в путях, текст интерфейса, значения атрибутов, приватные логи и исходники. Проверь его перед публикацией. Анализируй исходники, на доступ к которым у тебя есть разрешение.

## Проверка

Проверены синтаксис Lua и логика сбора/экспорта на тестовых объектах: метаданные, опциональные исходники, запасная декомпиляция, фильтр экспорта и выгрузка. В реальном клиенте Roblox и конкретной среде выполнения скрипт здесь не запускался; работа GUI и предоставляемых средой API требует проверки на месте.
