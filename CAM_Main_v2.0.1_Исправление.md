# CAM Main 2.0.1 — исправление самопроизвольного STOP

**Основной файл: `CAM_Main_Hub_v2.0.1.lua`.** Это самостоятельный main, не debug и не добавка к старому скрипту.

## Что показал отчёт

На версии игры 5400 main 2.0 обнаружен и работает: все 11 штатных модулей готовы, квест на медвежат распознан, Tanto экипируется, наблюдаются комбо и уменьшение HP цели.

Причина зафиксированной аварийной остановки:

```
12:45:46  callback error  :6272: table index is nil
12:45:46  stop            Callback failed; see diagnostics
```

Та же ошибка повторилась в 12:45:47 и 12:45:51. Первая смена Auto Level ON → OFF зафиксирована на 29,399 секунды записи, при HP 147/147. Это не остановка по низкому HP.

В выданном файле v2.0 строка 6272:

```lua
if o:IsA("Humanoid") then C.humanoids[o.Parent]=nil end
```

Во время удаления/выгрузки объекта `Parent` уже может быть `nil`. Запись по ключу `nil` вызывает исключение, а общий обработчик ошибок вызывает STOP ALL. Для этого не обязательно удаляться текущей цели: обработчик наблюдает объекты всего загруженного мира.

Сообщение на скриншоте про `Loading allowlisted native controls` — обычное уведомление о подключении модулей, не сообщение об ошибке.

## Что изменено

- Родитель Humanoid запоминается при индексировании.
- Обработчик удаления безопасен при пустом Parent и повторных событиях удаления.
- Позднее удаление старого Humanoid не удаляет из индекса его замену.
- При исчезновении текущей цели очищаются выбор цели и удержание позиции. Сам по себе этот случай больше не вызывает общий STOP.
- Защиты по низкому HP, отсутствию урона, блокировке движения и настоящим ошибкам сохранены.
- В диагностике появился `lastStop`: причина и состояние непосредственно перед остановкой, отдельно от текущего текста статуса.
- Журнал снимка копируется: события, произошедшие позже, больше не дописываются задним числом в `runtimeBefore` сборщика.
- Уведомление о подключении модулей стало понятнее; ошибки добавления/удаления объектов содержат название обработчика.

Маршруты квестов, боевые алгоритмы, позиционирование и настройки расходов не менялись. Новые функции из общего списка в этот узкий исправляющий выпуск не добавлялись.

## Как заменить

1. В старом main нажми **Unload hub**.
2. Выполни полностью **`CAM_Main_Hub_v2.0.1.lua`**.
3. На странице **auto level** включи **Auto Level - accept / farm / repeat**.

Все автоматизации по-прежнему запускаются выключенными. **RightCtrl** — меню, **End** — STOP.

Если снова случится остановка, в самом main есть **diagnostics / limits → ONE CLICK - save + copy main diagnostics**. В новом отчёте будет поле `lastStop`. Повторный большой сбор исходников для этого не требуется.

## Проверка

На имитации API воспроизведена исходная ошибка: v2.0 выключает Auto Level после удаления Humanoid без Parent. Исправленная версия проходит этот случай, повторное удаление, оба порядка удаления модели/Humanoid, замену Humanoid, очистку зависания, замороженный журнал и сохранение защитных STOP.

Также пройдены прежние сценарные тесты квестового цикла, экипировки, восьми позиций, выбора целей, cooldown, ограничений и экспорта. Проверен синтаксис самостоятельного файла и воспроизводимая сборка.

**Это не live-проверка v2.0.1 в Roblox/Potassium. Исправлен подтверждённый дефект, но отсутствие всех возможных других остановок не обещается.**
