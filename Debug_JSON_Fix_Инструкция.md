# Debug 1.4 — исправление JSON-экспорта

Основной файл: **Debug_JSON_Fix_v1.4.lua**. Самостоятельный скрипт со встроенным Lumen UI; запускай целиком вместо версии 1.3.

## Что сделать сейчас

1. Запусти новый файл.
2. Нажми **scan → Game overview (no source)** и дождись завершения.
3. Открой **export**. После этого профиля выбран **Full report**.
4. Лучше нажми **Save report (.json)** и пришли созданный файл. Если файловый API недоступен — **COPY REPORT** или ручное копирование.

**CORE повторять не нужно:** присланный отчёт с 87 исходниками сохранён для анализа, в нём отсутствующих запрошенных корней и зарегистрированных ошибок нет.

Новая версия заменяет окно прежнего сборщика. Старые сканы, хранившиеся только в памяти прежней версии, не переносятся автоматически — overview нужно выполнить заново.

## Что изменено

Ошибка `JSON error: Can't convert to JSON` возникала до обращения к буферу: штатный HttpService:JSONEncode отказывался сериализовать отчёт. По одному скриншоту нельзя достоверно определить, какое значение или ограничение вызвало отказ.

Теперь:

- сначала используется штатный JSONEncode;
- при отказе отдельно проверяются верхние поля отчёта, чтобы отметить проблемные разделы;
- включается независимый JSON-экспорт без зависимости от JSONEncode;
- повреждённые последовательности UTF-8 заменяются символом U+FFFD;
- NaN, Infinity, циклические ссылки и таблицы глубже 64 заменяются на null с записью причины;
- неподдерживаемые значения переводятся в текст; конфликтующие имена ключей сохраняются с различающими суффиксами;
- исправления явно фиксируются, исходный объект отчёта в памяти не изменяется;
- кнопки копирования, сохранения, ручного просмотра и экспорта всех сканов используют один исправленный механизм;
- большой запасной экспорт периодически отдаёт управление интерфейсу;
- **Cancel** может остановить экспорт, не удаляя уже собранный скан. После отмены можно повторить экспорт.

Это обработка проблем сериализации, а не гарантия отсутствия любых ограничений памяти, файлового API или буфера среды выполнения.

## Диагностика в JSON

Если использовался запасной механизм, появляется поле **`_jsonExport`**:

| Поле | Что означает |
|---|---|
| `nativeError` | Сообщение штатного кодировщика |
| `nativeFailedFields` | Какие верхние поля также не удалось сериализовать штатным методом |
| `normalizationCount` | Число зарегистрированных нормализаций |
| `changedValues` | Менялись ли значения при нормализации |
| `issues` | До 100 описаний: путь к значению, тип проблемы и выполненная замена |
| `issueDetailsTruncated` | Есть ли дополнительные нормализации, не вошедшие в первые 100 описаний |

Например, путь в `issues` может указывать на конкретный элемент массива `nodes` и его `name`/`path`/атрибут.

**Нормализация повреждённых строк не является побайтовым сохранением исходных данных.** Если changedValues=true, учитывай перечисленные изменения. При обычном успешном JSONEncode поле `_jsonExport` не добавляется. При запасном экспорте с normalizationCount=0 данные удалось представить без зарегистрированных замен — причиной прежнего отказа могло быть ограничение самого штатного кодировщика, но этот вывод не считается доказанным автоматически.

Статусы `stats.incomplete`, `treeIncomplete` и `sourceIncomplete` описывают сканирование, а `_jsonExport` — последующий экспорт. Это разные этапы; нормальный экспорт не делает частичный скан полным.

## Большие отчёты

Для overview предпочтительно сохранение файла. Некоторые реализации буфера могут ограничивать размер или молча обрезать текст; успешный вызов setclipboard не подтверждает его целостность. Ошибка файлового API или буфера будет показана отдельно от JSON-ошибки.

Все лимиты обхода, исключение CorePackages, профили CORE/ReplicatedStorage/Local client и единый экспорт ALL scans сохранены. Игровые remotes не вызываются, найденные модули не запускаются, отчёты по сети не отправляются.

## Проверка

Проверены:

- синтаксис полного Lua-файла;
- регрессия прежних профилей и экспорта;
- запасной экспорт при искусственном `Can't convert to JSON`;
- копирование/сохранение overview и объединённого отчёта;
- Unicode, управляющие символы, повреждённый UTF-8, недопустимые числа, циклы, общие ссылки, конфликтующие ключи и ограничение глубины;
- сохранение всех **87 присланных текстов исходников без изменения** при прогоне через запасной кодировщик;
- отмена экспорта и повторная попытка без потери кэша сканов.

Тесты выполнены на моделируемых объектах и присланном CORE-отчёте. **Проблемного overview у меня нет; в твоём живом Roblox-клиенте версия ещё не проверена.**
