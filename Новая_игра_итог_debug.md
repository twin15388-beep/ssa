# Новая игра: результат проверки CORE и overview

## 1. Экспорт исправлен

Полученный `Текстовый документ (2).txt` — корректный JSON формата `NZL Game Debug 1.4`, профиль `overview`, размер 13 869 442 байта. Файл полностью разобран JSON-парсером; это не лог и не исходный код сборщика.

Диагностика `_jsonExport`:

- штатный кодировщик вернул `Can't convert to JSON`;
- проверка верхнего уровня локализовала отказ в поле `nodes`;
- запасной кодировщик `portable-json-v1` успешно сформировал отчёт;
- `normalizationCount = 2135`, `changedValues = true`;
- сохранены первые 100 записей диагностики, все они — `invalid_utf8`; остальные детали обрезаны (`issueDetailsTruncated = true`). Число 2135 — счётчик нормализаций, а не число объектов или повреждённых байтов.

В показанных случаях проблема находится в строковых атрибутах эффектов: `Part_CFrame_Curve`, `Speed_Curve`, `SpinSpeed_Curve`, `Size_Curve`, `Transparency_Curve` и других. Пример объекта: `ReplicatedStorage.Effects.Flame Breathing.Blazing UniverseVFX.BeamSlash`. Эти значения содержат байты, не образующие корректный UTF-8; обращаться с ними как с обычным текстом нельзя.

В экспортной копии некорректные байты заменены символом U+FFFD. Их исходные значения из этого JSON уже не восстановить. Объекты игры при этом не изменялись. Для побайтового исследования самих кривых в будущем понадобился бы экспорт таких строк в Base64/hex; для текущего разбора клиентской логики повторный сбор не требуется.

## 3. Что добавил полученный ранее CORE

CORE сохранён отдельно: 87 текстов исходников, все 25 запрошенных корней разрешены, без заявленных обрезаний или ошибок. Тексты извлечены в `new_game_analysis/core_sources/`, индекс — `manifest.json`. Найденные модули не исполнялись.

Предварительная проверка ключевых модулей:

- **Квесты.** В `CAM.Global.Subsets.Gameplay.Quests` указаны `QuestCD = 30` и `MaxQuestsPerPlayer = 1`. Это значения в полученном модуле, не доказательство отсутствия других серверных ограничений.
- **Выбор рекомендуемого квеста.** `RecommendedQuest` требует `Book of Guidance`, проверяет `CanAddQuest`, рассматривает подходящие задания категории Combat и предпочитает максимальный доступный требуемый уровень; при равенстве — меньшую дистанцию до NPC. Позиция берётся через `Regions.GetNpcSpawn`. Это рекомендация, а не готовый протокол автоматического принятия и сдачи.
- **Способности.** В `Skill_Controller` видны обращения через `server_skill_controller_signaler` и состояния `Switch`, `Hold`, `UnHold`, `Cancel`, `Counter`, `UnHoldAfterClient`. Это подтверждает наличие многошагового клиентского протокола, а не возможность безусловно вызывать любую способность.
- **Стамина.** `StaminaComponent` читает `Stamina.Value / Stamina.MaxValue`, слушает `Stamina.Changed` и уведомление `NotEnoughStamina`, обновляет интерфейс. В этом модуле не найдено механизма отключения расхода; обещать бесконечную стамину оснований нет.
- **Транспорт.** `SignalEvent` и `SignalFunction` используют RemotePlus и делегируют отправку в `EventerMain` / `InvokerMain`. Это согласуется с архитектурой, найденной в предыдущих исходниках.

Декомпилированный текст может содержать ошибки восстановления. Проверка здесь статическая, не испытание функций в живом клиенте.

## Итог

Сбой JSON-экспорта обойдён в реальном присланном отчёте, а проблемные значения локализованы. CORE и доступная часть overview сохранены; повторять те же сборы сейчас не нужно. Материал пригоден для дальнейшего разбора клиентского боя, способностей и квестов. Полнота карты мира, готовность авто-квеста и обход серверных ограничений этим отчётом не подтверждаются.
