# CAM Main Hub v1.0 — инструкция и матрица функций

**Основной файл: `CAM_Main_Hub_v1.0.lua`. Он самостоятельный: Lumen UI и резервный JSON-кодировщик уже внутри.** Другие Lua-файлы скачивать не нужно.

Это новая реализация для PlaceId **136406881576517**, по исходникам версии места **5354**. Она не использует remotes и механики старой игры. На другом PlaceId игровые переключатели блокируются; это не универсальный скрипт для данжей и лобби.

Выбранный объём: **максимум функций, обоснованных доступным клиентским кодом**, без неработающих переключателей для всего рекламного списка. «Реализовано» ниже означает наличие реализации и проверку логики в имитационном окружении, **не подтверждённую работу в живом клиенте**. Исполнитель, изменения игры и серверные проверки могут ограничить функции.

## Быстрый старт

1. В старом debug нажми **Unload collector**, чтобы не оставлять два меню на RightControl.
2. Запусти **весь** `CAM_Main_Hub_v1.0.lua` в клиенте нужной игры.
3. В `dashboard` нажми **Connect native controls**. Подожди загрузки. Для атак нужен `InputHandler`; для рекомендаций и Boss Hunts — соответствующие модули. Если статус не готов, сохрани диагностический отчёт.
4. В `farm / combat` выбери **Target type → Refresh loaded targets → Exact NPC name**. Выбирай именно противника. Неопознанный неигровой Humanoid считается кандидатом Mob, а не доказанно враждебной целью.
5. Экипируй оружие штатно или кнопкой выбора существующего toolbar-слота. Проверь **M1 once**, затем включай нужную автоматизацию.
6. Для навыков сначала отметь нужные **Use skill input slot N**, затем включи **Auto Skills**. Первый слот может быть блоком; не включай все подряд.

**RightControl** — показать/скрыть меню. **End** — общий STOP, включая нажатия, движение и ESP. **Unload hub** — полный выход и удаление интерфейса.

Все переключатели изначально выключены. Автозагрузка конфигурации отключена. После STOP также очищается выбор активных skill-input слотов — их нужно отметить заново. Смерть, смена персонажа или команды выключают функции. Низкий HP останавливает активные автоматизации, без автоматического перезапуска.

## Что реализовано

### Бой и фарм

- **Auto Farm selected NPC**: выбирает ближайшую живую модель с точным выбранным именем в указанном радиусе, идёт через `Humanoid:MoveTo` и нажимает штатный `Combat`.
- **Auto M1**: то же нативное управление атакой, но без движения.
- **Auto Boss**: режим Target type = Boss. Имена взяты из `BossHunts.Hunts` и шаблонов `Assets.Npcs.Bosses` в предоставленных данных; это классификация по известным именам, не универсальное распознавание всех боссов.
- Игроки исключаются через `Players:GetPlayerFromCharacter`, собственный персонаж также исключён. Диалоговые/скрытые NPC, GauntletStatue и модели с ProximityPrompt исключены из боевых целей.
- Дистанция M1, интервал, расстояние остановки и порог HP настраиваются. Радиус поиска **не увеличивает дистанцию нанесения урона**.
- Перемещение — прямой `MoveTo`, без полноценного обхода препятствий. Если персонаж не продвигается, фарм останавливается.
- **Auto Skills**: циклические виртуальные нажатия выбранных штатных `Skills_1st` … `Skills_10th`, с регулируемым удержанием и интервалом. Игра сама определяет доступность навыка, расход и откат. Наведение остаётся штатным — мышь/камера; перехвата aim нет.

Не подставляется выдуманный `Combat_Service` payload. Используются найденные в `InputHandler` методы `VirtualPress`, `VirtualRelease`, `IsDown`. Без доступного нативного управления фарм не начинает идти к противнику.

### Квесты и Boss Hunts

- Просмотр рекомендации через штатный `RecommendedQuest.Get()`.
- Телепорт к возвращённой игрой позиции NPC, если она доступна. Для штатной рекомендации обычно нужен **Book of Guidance** и выполнение условий доступности.
- Отображение имён текущих активных заданий.
- Просмотр текущих Boss Hunts подходящей расы; в диагностический лог выводятся ID, квест и босс.
- Принятие **выбранного ID** через подтверждённый вызов `SignalEvent.ToServer("BossHuntsRequest", {action="Claim", id=...})`, с проверкой срока и `Quests.CanAddQuest`.
- Автоматический вариант — одна заявка для выбранного ID, без бесконечных повторов. STOP сбрасывает защиту от повторной заявки. Новые ID не выбираются автоматически.

**Это не полный Auto Level / Auto Farm Quests:** универсальный цикл «взять → найти цели → выполнить → сдать → перейти к следующему заданию» не реализован. Auto Boss Hunts здесь — частичное управление принятием задания, а не полностью автономный цикл.

### Лут и сундуки — частичная поддержка

- **Auto Loot** работает только с доступным `ProximityPrompt` внутри распознанного LootDrop / `Workspace.LootDrops`.
- **Auto Chest** — аналогично для `Workspace.Chests` / `ChestGuid`; объекты с `ChestState = Locked` пропускаются.
- Проверяются Enabled, штатная дистанция и линия видимости, если она требуется. Нет автоматического притягивания, телепорта к каждой награде или угадывания remote-вызовов.
- Взаимодействие — `InputHoldBegin / InputHoldEnd` с паузой между попытками.
- **Instant ProximityPrompt** сокращает локальный HoldDuration для взаимодействий через хаб; исходное значение восстанавливается при отключении/STOP. Это не обход серверного таймера и не глобальная модификация всех prompts.
- Если в этой сессии у сундука/лута нет ProximityPrompt, автоматический сбор для него **не поддерживается**. В статусе будет указано отсутствие подходящего prompt, а не ложное сообщение о получении награды.

### Перемещение и телепорты

- **Fly**: WASD, Space вверх, LeftCtrl вниз. Для мобильного управления — стик и кнопки короткого подъёма/спуска. Используются локальные LinearVelocity/AlignOrientation; они удаляются при выключении.
- **Noclip**, **Speed**, **High Jump**: локальные изменения с запоминанием исходных значений. Режим JumpPower/JumpHeight учитывается.
- **Always Run**: удержание штатного действия Run. Поведение зависит от нативной настройки игры «удерживать/переключать»; не заявлено снятие затрат или штрафов бега.
- **Disable Shift Lock**: через найденный `Run_Handler.SetShiftLock`, с восстановлением прежнего значения.
- **Zone / NPC / Mob / Boss / Muzan / Chest / Loot / Spider Lily / Lever / Training Teleport**: по текущим загруженным объектам и их реальной позиции, без выдуманной таблицы координат.
- **Save current position / Return to saved position**: сохранение в памяти текущей сессии.
- **Ownership Viewer**: показывает принадлежность локальному клиенту только при наличии `isnetworkowner`. Иначе честно сообщает unknown; владельца-сервер/другого игрока не угадывает.

Ручной телепорт прекращает фарм, автоматические атаки/навыки и Fly. При заметной коррекции сервером не запускаются бесконечные повторные телепорты. Возможность двигать собственный персонаж не означает право управлять NPC.

### ESP и уведомления

Реализованы **Box, Box Fill, 3D Box, Name, Distance, Health Text, Health Bar, Tracer**. Категории: игроки, кандидаты Mob, известные Boss, диалоговые NPC, сундуки, лут, Muzan, Spider Lily, Lever и точное имя Wild Horse.

- Для включения: **Enable ESP + категория + стиль**. Есть кнопка **Enable basic mob / boss ESP**.
- Health показывается только при наличии Humanoid.
- Ограничены дистанция и число отрисовываемых объектов; Drawing API не нужен.
- NPC/Mob — эвристическая классификация; Boss — известные имена; Wild Horse — точное имя, не подтверждённый универсальный классификатор лошадей.
- Доступны уведомления о появлении загруженного объекта босса/Muzan и о новом подходящем Boss Hunt.
- При StreamingEnabled «объект появился у клиента» **не равно** «босс только что заспавнился на сервере». Объекты вне клиентской репликации не видны.

### Приоритеты и ограничения действий

Приоритет безопасности: STOP/смерть/недоступный персонаж → ввод текста/нативное меню → низкий HP → ручной Fly. Далее применяется **Combat first / Loot first**. Удерживаемый prompt приостанавливает движение/боевые действия хаба. Автозаявки Boss Hunt ожидают, пока выключены боевые режимы.

Это небольшой планировщик реализованных функций, а не автоматическое управление отсутствующими системами очередей, данжей или покупок.

## Безопасность реализации и диагностика

- Нет загрузки кода по HTTP, decompile, игровых hooks, обращения к админским OCIFolder-командам или передачи данных вовне.
- В отличие от read-only debug, **этот main выполняет игровые действия после включения функций**. Кнопка Connect разрешает `require` только шести перечисленных в коде живых модулей. Их собственная штатная инициализация может иметь побочные эффекты. Загруженные пользователем тексты не исполняются.
- Нативные модули загружаются отдельно, с ограничением ожидания 10 секунд. Если загрузка не удалась, соответствующая функция недоступна, а не заменяется выдуманным remote.
- Изменённые локальные свойства восстанавливаются к сохранённым до включения значениям. Нативные уже отправленные запросы, нанесённый урон или завершённое взаимодействие отменить невозможно.
- STOP отпускает только ввод, который инициировал хаб; физически удерживаемые пользователем действия не присваиваются ему.
- Автоматизация может нарушать правила игры. Клиентские изменения могут быть отвергнуты или откорректированы сервером.

При проблеме: **diagnostics / roadmap → Save diagnostic JSON** и пришли файл. Также есть **COPY diagnostic report** и ручное окно копирования. Отчёт содержит статус модулей, настройки, выбранную цель и журнал; в нём нет webhook-адресов или специально собранных приватных токенов. Резервный кодировщик из исправленного debug включён.

## Источники и проверки

Основания: `InputHandler` (VirtualPress/VirtualRelease), клиентский `Combat` (ListenTo Combat), `Run_Handler`, `Utility.ForceEquip`, `RecommendedQuest`, `Quests.CanAddQuest`, `HuntCard` (BossHuntsRequest), `DialogueComponent.Components.Quests` (реплицированные hunt ID / Side / ExpiresAt), `ChestController`, `ChestSeal`, `LootDropController` и полученный обзор дерева. Исходники декомпилированы и могут содержать ошибки восстановления.

Пройдено: проверка синтаксиса standalone-файла; имитационные тесты отсутствия стартовых игровых запросов/require; блокировки до подключения native; исключения игроков; отпускания ввода и отмены задержек; сброса skill-слотов; payload/race/dedup Boss Hunt; отката движения; Fly; смерти/респавна; locked/out-of-range prompts и восстановления HoldDuration; отрисовки ESP; неверного PlaceId; экспорта и выгрузки. Дополнительно повторены тесты резервного JSON-кодировщика.

**Живой Roblox-клиент здесь недоступен.** Эти проверки не являются заявлением о прохождении античита, успешном нанесении урона или получении наград на сервере.
