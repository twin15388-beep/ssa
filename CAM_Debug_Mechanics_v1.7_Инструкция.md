# CAM Mechanics Debug 1.7 — одна кнопка

**Файл:** `CAM_Debug_Mechanics_v1.7.lua`.

Это отдельный сборщик, не обновление main. Он собирает материалы для оставшихся функций и записывает, почему Auto Level переходит из ON в OFF. Работающий цикл v2.0 не заменяется и его защитные остановки не отключаются.

## Первый запуск: Auto Level и его выключение

1. **Оставь CAM Main v2.0 загруженным.** В отличие от прежнего debug, останавливать фарм ради этого сбора не нужно.
2. Выполни весь `CAM_Debug_Mechanics_v1.7.lua`.
3. Нажми **START 90s + COLLECT + SAVE + COPY** — один раз.
4. Пусть Auto Level работает. Debug можно скрыть через **RightShift**; main скрывается через **RightCtrl**.
5. Сборщик запишет **90 секунд**. Затем проверит появившиеся/ранее не собранные скрипты; это может занять ещё примерно 25 секунд плюс экспорт.
6. Он автоматически сохранит **`CAM_Debug_Mechanics_<PlaceId>_<дата-время>.json`** в файловой папке исполнителя и попытается скопировать **тот же JSON** в буфер.
7. Пришли сохранённый JSON — он предпочтительнее вставки большого текста из буфера.

**Если Auto Level уже сам выключился:** не выгружай main и по возможности не нажимай его STOP перед сбором. В его журнале может сохраняться точная причина. Сборщик забирает этот журнал в начале, даже если новое выключение за 90 секунд не случится.

Если во время записи ты сам нажал End/STOP, это тоже будет остановка. Её нельзя путать с самопроизвольным выключением: в журнале остаётся текст причины.

## Что делать для остальных функций

Сборщик ничего не демонстрирует за тебя. Он наблюдает за обычными действиями и автоматически выбирает доступные скрипты — пути, фильтры и лимиты вручную вводить не надо.

| Что исследуем | Что показать во время отдельной записи |
|---|---|
| Обычная стамина / бой | Несколько обычных рывков, бег, блок и доступная способность; затем восстановление. Для чистоты такой опыт лучше проводить отдельно от автоматического фарма. |
| Лазание / лошадь | Лазание по доступной поверхности; для лошади — езда, если она уже доступна. Это отдельные механики расхода. |
| Рыбалка | С уже имеющейся удочкой — заброс, поклёвка, обычная попытка вываживания. Если удочки нет, достаточно пока открыть доступный интерфейс/магазин: специально покупать её ради сбора не нужно. |
| Обучение / дыхание / skill tree | Открыть NPC-диалог и дерево навыков. Если мини-игра уже доступна — пройти попытку. Не подтверждать покупки, трату очков или смену расы только ради debug. |
| Магазины / экипировка | Открыть нужный магазин и инвентарь, посмотреть категории и требования. Покупки не обязательны. |
| Очередь | Открыть окно выбора режима/очереди и показать доступные параметры. |
| Подземелье / волны / карточки | **Сначала войти в режим**, там снова выполнить сборщик и нажать ту же кнопку. По возможности запись должна захватить начало волны или появление выбора карточек. |

**Не требуется сразу делать все записи.** Начни с Auto Level в основном мире. Для разных режимов будут отдельные файлы: один отчёт основного мира не показывает скрипты, которые ещё не реплицированы в другом месте.

Сборщик не переносится автоматически через телепорт. Запись запускай уже после загрузки нужного места. Если уходишь на другой сервер во время записи, текущий отчёт может не успеть сохраниться.

## Что попадает в отчёт

### Работа main

- снимок main до и после записи;
- переходы состояния, включая **Auto Level ON → OFF**;
- точный текст статуса и доступный журнал остановок;
- фаза, выбранный квест, прогресс, экипировка и счётчики попыток/комбо/наблюдения HP.

### Наблюдения во время действий

- изменения локальных игровых значений примерно каждые 0,5 секунды;
- HP, stamina и её границы, EXP, Wen, задания, powers и skill-tree values;
- некоторые общие значения текущего режима и атрибуты мира/персонажа;
- событие `NotEnoughStamina`, если доступно;
- до 12 ближайших неигровых Humanoid в пределах 200 studs: HP, позиция, атрибуты, доступная информация о network ownership;
- события HP, локального `Died`, исчезновения модели из Workspace и запуска анимации для наблюдаемых NPC;
- числовые ID NPC внутри записи, чтобы отличать модели с одинаковыми именами;
- снимки видимых тематических игровых интерфейсов примерно раз в 15 секунд. Чат и текстовые поля не записываются этим UI-снимком.

### Исходники

Приоритеты: stamina/бой, fishing, training/skill tree, квестовые механики, магазины/предметы, queue/minigame/waves/cards, раса и текущий режим.

- читается доступный `Source`, иначе используется предоставленный исполнителем `decompile`;
- в первом проходе выбираются до 350 исходников, в заключительном — до 80 дополнительных;
- исходники не выполняются через `require`;
- большая часть уже присланного нетематического контента на том же PlaceId/version указывается ссылкой на старый отчёт, а не копируется заново;
- тематические модули перечитываются для актуальной версии;
- учитываются новые скрипты, появившиеся во время записи;
- если лимит не позволил прочитать всё, сохраняются счётчики и список отложенных кандидатов.

CorePackages, CoreGui, пакеты, тяжёлые Assets/Effects, модели-шаблоны и деревья данных других игроков не обходятся. В общем состоянии режима дополнительно пропускаются ветки roster/player data. Общие игровые логи и исходники всё же могут содержать имена/другие данные — просмотри отчёт перед отправкой.

## Стамина и instant kill: как читать результаты

В уже имеющихся исходниках:

- `StaminaComponent` и Character `Stamina` отвечают за отображение полоски;
- `Skills_Module` рассчитывает стоимость способности с `Stamina Cost Factor` и содержит списание в ветке `RunService:IsServer()`;
- лазание использует отдельные `CurrentStamina / MaxClimbTime`;
- у лошади есть отдельный клиентский счётчик и `StaminaDrain`.

Это основание исследовать механики отдельно, **не доказательство, что любое изменение клиентского значения даст бесконечную серверную стамину**. Новый debug только читает состояние — он пока не реализует Infinite Stamina.

Для instant kill отдельно важны:

- изменился ли HP;
- был ли только локальный `Died`;
- исчезла ли модель/упала ли за пределы мира;
- изменились ли квестовый счётчик, EXP или Wen;
- кому принадлежала физика NPC, если API это позволяет узнать.

Уменьшение HP, исчезновение модели и принадлежность физики **не доказывают** серверное убийство или получение награды. Сборщик сам не убивает и не удаляет NPC и не доказывает конкретную реализацию чужого instant kill.

Если у тебя есть сам код или видео уже работающей реализации, его можно прислать отдельно. Для запуска этого debug оно не требуется.

## Кнопки и ограничения

- **START 90s + COLLECT + SAVE + COPY** — основной сценарий, одна кнопка.
- **FINISH NOW - save partial recording** — закончить раньше и выгрузить явно неполный результат.
- **Save + copy last report again** — повторить экспорт сохранённого в памяти результата.
- **Unload debug** — снять наблюдатели и выгрузить debug. Незавершённая запись при выгрузке не обязана сохраниться; для сохранения используй FINISH NOW.

Сборщик не нажимает игровые клавиши, не покупает, не расходует очки, не меняет статы, не вызывает игровые remotes и не перехватывает исходящие вызовы. Действия запущенного main и твои ручные действия при этом продолжаются — debug не блокирует их и не снимает ответственность за расходы ручного действия.

Если clipboard API недоступен, остаётся файл. Если сохранение недоступно — используется буфер. Если оба способа не сработали, открывается текст для ручного копирования. Подтверждение вызова clipboard API не является проверкой целостности системного буфера.

Запись, обход и объём исходников ограничены. Лимиты, ошибки декомпиляции, пропуски времени и частичные данные отмечаются в JSON. Декомпиляция может замедлять игру; тайм-ауты и отмена зависят от поведения исполнителя и не являются жёсткой гарантией реального времени.

**Проверено:** синтаксис и имитационные тесты — переход main в OFF, stamina/события NPC, новые скрипты, лимиты и тайм-ауты, раннее завершение, идентичный сохранённый/скопированный JSON, запасной JSON-сериализатор, ошибки экспорта и очистка наблюдателей. Реального запуска 1.7 в Potassium автор не выполнял.
